# CodexTask 远程服务与移动端接入方案

## 背景

CodexTask 目前以 CLI 和 TypeScript API 运行。手机无法直接启动本机 CLI，而且 text、image、task 的执行时间可能从数秒延伸到数十分钟，普通同步 HTTP 请求容易被移动网络或系统后台策略中断。

## 目标

增加一个随 npm 包发布的 `codex-task serve`，让可信手机通过统一的异步 HTTP 接口提交 text、image、task 和 resume。Ubuntu、macOS 和 Windows 提供显式安装脚本，使服务在对应用户登录后自动启动并复用该用户的 Codex OAuth、配置、skills 和 sessions。

## 接口方案

```text
POST /v1/text
POST /v1/image
POST /v1/task
POST /v1/tasks/:taskId/resume
GET  /v1/jobs/:jobId
GET  /v1/jobs/:jobId/artifacts/:index
GET  /healthz
```

提交接口立即返回 `202 + jobId`。手机轮询 job，终态沿用 `completed | needs_input | failed | cancelled`。图片和文件通过需要同一 Bearer Token 的 artifact URL 下载。

远端 Input Part 使用 JSON：inline prompt、多个 `{name, content}` UTF-8 prompt 文件，以及多个 `{name, mimeType, dataBase64}` 图片。服务不接受客户端伪造的服务器本地 input path；上传图片只在任务运行期间物化到 CodexTask 临时目录。

## 安全边界

- 默认只监听 `127.0.0.1:7777`。
- 监听非 loopback 地址时必须配置 Service Token，否则拒绝启动。
- Token 只从权限收紧的文件或 `CODEX_TASK_SERVER_TOKEN` 读取，不写入命令行和仓库。
- 原生手机不需要 CORS；服务不默认提供浏览器跨域访问。
- 服务不内置 TLS。跨设备推荐 Tailscale、WireGuard 或带 HTTPS 的可信反向代理，不应直接暴露到公网。
- Token 持有者等同拥有该用户的 CodexTask 权限。尤其 `task` 默认 `danger-full-access`、network enabled、approval never。

## 部署方案

持久服务使用 `npm install -g codex-task@latest`，不使用 `npx`。全局安装让启动不依赖网络，并固定实际执行文件；升级由安装脚本重跑或 `npm update -g codex-task` 显式触发。

| 平台 | 自动启动机制 | 时机 | 原因 |
| --- | --- | --- | --- |
| Ubuntu | systemd user service | 用户会话启动；启用 linger 后可随系统启动 | 保留用户 Codex Home 和 OAuth |
| macOS | LaunchAgent | 用户登录 | LaunchDaemon 无法自然复用用户 Codex 环境 |
| Windows | Scheduled Task | 用户登录 | 直接包装 Node CLI 为 Windows Service 需要额外 service host |

安装脚本负责安装 npm 包、生成 token 文件、写入启动配置并启动服务；卸载脚本只删除自动启动配置，不删除 Codex sessions、任务产物或全局 npm 包。

## 验收

1. HTTP 测试通过真实 socket 验证 health、鉴权、异步提交、轮询、resume 和 artifact 下载。
2. 非 loopback 无 token 时服务拒绝启动。
3. 三个平台均有安装与卸载脚本，脚本不把 token 放进进程参数。
4. Android Kotlin 和 iOS Swift 示例覆盖提交、轮询、resume、图片上传与 artifact 下载。
5. README、PRD、Skill 与常用命令明确权限边界和部署时机。

## 实施结果

- 服务实现：`src/server.ts`，CLI 入口为 `codex-task serve`，TypeScript API 导出 `startCodexTaskServer()`。
- 部署脚本：`scripts/service/`，覆盖 Ubuntu、macOS、Windows 的安装与卸载。
- 手机示例：`examples/mobile/`，Android/iOS 均串联 image、text、task、resume。
- 自动清理：正常终态删除整个上传 job 目录；服务启动时清理超过 job TTL 的崩溃残留目录。
- npm 打包检查确保服务脚本和手机示例随包发布。
- 自动化验证覆盖真实 HTTP socket、鉴权、并发排队、轮询、追问恢复、artifact 下载与临时上传清理。

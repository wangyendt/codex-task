# CodexTask 远程服务部署与移动端调用

## 结论

持久服务使用全局安装：`npm install -g codex-task@latest`。不要把 `npx codex-task@latest serve` 写进开机启动项，因为它可能在启动时访问 npm、受网络故障影响，并且 `latest` 指向的版本可能在未验证时变化。

CodexTask 提供用户级自启动，而不是系统级 root 服务。这样它能复用当前用户的 `$CODEX_HOME`、OAuth、配置、skills 和 sessions：

| 平台 | 文件 | 机制 | 实际启动时机 |
| --- | --- | --- | --- |
| Ubuntu/Linux | `scripts/service/install.sh` → `install-ubuntu.sh` | systemd user service | 默认启用 linger，可在开机后、用户未登录时启动 |
| macOS | `scripts/service/install.sh` → `install-macos.sh` | LaunchAgent | 用户登录 |
| Windows | `scripts/service/Install-Windows.ps1` | Scheduled Task | 用户登录 |

## 安装

先确认 Node.js 20+、npm 和 Codex 登录可用：

```bash
node --version
codex login
```

从仓库运行 Unix 统一安装脚本；它会自动识别 Ubuntu/Linux 或 macOS：

```bash
git clone https://github.com/wangyendt/codex-task.git && cd codex-task && bash ./scripts/service/install.sh
```

Windows PowerShell：

```powershell
git clone https://github.com/wangyendt/codex-task.git; Set-Location codex-task; powershell -ExecutionPolicy Bypass -File .\scripts\service\Install-Windows.ps1
```

安装器默认监听 `0.0.0.0:7777`、最大并发 2，生成 32 字节随机 token，并打印 token 文件与日志位置。可以在运行安装器前覆盖：

```bash
CODEX_TASK_SERVICE_HOST=127.0.0.1 CODEX_TASK_SERVICE_PORT=8787 CODEX_TASK_SERVICE_CONCURRENCY=1 bash ./scripts/service/install.sh
```

PowerShell 对应写法：

```powershell
$env:CODEX_TASK_SERVICE_HOST="127.0.0.1"; $env:CODEX_TASK_SERVICE_PORT="8787"; $env:CODEX_TASK_SERVICE_CONCURRENCY="1"; .\scripts\service\Install-Windows.ps1
```

在 Ubuntu/Linux 上，安装器会默认为当前用户启用 linger，首次可能要求输入 `sudo` 密码。安装后可检查：

```bash
loginctl show-user "$USER" -p Linger
```

期望输出为 `Linger=yes`。卸载 CodexTask 不会关闭 linger，避免影响该用户的其他 systemd user service。

macOS LaunchAgent 和 Windows Scheduled Task 是登录启动，不是在登录前运行；这是为了复用正确的用户 Codex 环境。

## 给设备创建受限 Token

安装脚本生成的是全权限主 Token，保留它用于管理和确实需要 `task`/`resume` 的可信客户端。只需要文本或图片的手机应使用独立设备 Token：

```bash
codex-task token create --name iphone-text --allow text
codex-task token create --name ipad-media --allow text,image
```

`create` 只在创建时返回一次完整 Token。把该值存入 Android Keystore、iOS Keychain 或其他受保护配置。查看名称和权限不会显示秘密：

```bash
codex-task token list
```

设备丢失或不再使用时按名称吊销：

```bash
codex-task token revoke iphone-text
```

创建和吊销会立即生效，不需要重启服务。这些命令和 `install.sh` 相互独立；可以先创建再安装，也可以在服务运行期间管理。设备 Token 只允许创建时列出的 Direct `text`/`image`，不能使用 SDK，也不能调用 `task` 或 `resume`。无效 Token 返回 `401`，权限不足返回 `403`。

## 日常运维

Ubuntu：

```bash
systemctl --user status codex-task.service
journalctl --user -u codex-task.service -f
systemctl --user restart codex-task.service
```

macOS：

```bash
launchctl print "gui/$(id -u)/com.wangyendt.codex-task"
tail -f "$HOME/Library/Application Support/codex-task/service/service.log"
launchctl kickstart -k "gui/$(id -u)/com.wangyendt.codex-task"
```

Windows PowerShell：

```powershell
Get-ScheduledTask -TaskName CodexTask | Get-ScheduledTaskInfo
Get-Content "$env:APPDATA\codex-task\service\service.log" -Wait
Restart-ScheduledTask -TaskName CodexTask
```

重新运行安装脚本会执行 `npm install -g codex-task@latest`，并保留已有 token。手动升级后应重启服务：

```bash
npm update -g codex-task && codex-task --version
```

卸载自启动配置但保留全局 npm 包和 Codex 数据：

```bash
bash ./scripts/service/uninstall.sh
```

统一脚本只删除当前平台的 systemd user service 或 LaunchAgent 及其 Service Token；不会执行 `npm uninstall`，也不会删除 `$CODEX_HOME`、Codex sessions 或普通项目文件。需要针对底层脚本排障时，可直接运行 `install-ubuntu.sh`、`uninstall-ubuntu.sh`、`install-macos.sh` 或 `uninstall-macos.sh`。

Windows：

```powershell
.\scripts\service\Uninstall-Windows.ps1
```

## 手动启动

只在本机测试时可监听 loopback，不配置 token：

```bash
codex-task serve --host 127.0.0.1 --port 7777
```

任何非 loopback 地址都必须有 token，否则服务拒绝启动：

```bash
node -e 'process.stdout.write(require("node:crypto").randomBytes(32).toString("base64url"))' > ./codex-task-token && chmod 600 ./codex-task-token && codex-task serve --host 0.0.0.0 --port 7777 --token-file ./codex-task-token
```

也可以设置 `CODEX_TASK_SERVER_TOKEN`，但 token 文件更适合服务管理器，且不会把 token 写进进程参数。

## HTTP 请求模型

健康检查不需要鉴权：

```bash
curl -sS http://127.0.0.1:7777/healthz
```

除健康检查外，所有接口都需要：

```text
Authorization: Bearer <Service Token>
Content-Type: application/json
```

提交文本任务：

```bash
curl -sS -X POST http://127.0.0.1:7777/v1/text -H "Authorization: Bearer $CODEX_TASK_TOKEN" -H 'Content-Type: application/json' -d '{"prompt":"总结以下要求","promptFiles":[{"name":"requirements.md","content":"只返回三条要点"}],"backend":"direct","reasoning":"medium"}'
```

典型提交响应：

```json
{
  "jobId": "9d968391-ec93-46ec-9452-1f2c3039ab31",
  "status": "queued",
  "statusUrl": "/v1/jobs/9d968391-ec93-46ec-9452-1f2c3039ab31"
}
```

轮询状态：

```bash
curl -sS http://127.0.0.1:7777/v1/jobs/9d968391-ec93-46ec-9452-1f2c3039ab31 -H "Authorization: Bearer $CODEX_TASK_TOKEN"
```

终态为 `completed`、`needs_input`、`failed` 或 `cancelled`。图片产物不会暴露服务器绝对路径，而是返回同样需要 token 的 `downloadUrl`。

## 四类任务的 JSON

图片任务支持文字、多份 prompt 文档和参考图片：

```json
{
  "prompt": "生成高蛋白版本",
  "promptFiles": [
    { "name": "style.md", "content": "俯拍，自然光，不要文字" }
  ],
  "images": [
    { "name": "meal.png", "mimeType": "image/png", "dataBase64": "iVBORw0..." }
  ],
  "quality": "high",
  "size": "1024x1024",
  "count": 1
}
```

提交到 `POST /v1/image`。`images` 支持 PNG、JPEG、WebP、GIF，最多 5 张，单张不超过 20 MiB、合计不超过 50 MiB。整个 JSON body 默认上限 72 MiB。

工作区任务提交到 `POST /v1/task`：

```json
{
  "prompt": "实现营养餐详情页并运行测试",
  "promptFiles": [
    { "name": "requirements.md", "content": "页面需要显示总热量" }
  ],
  "images": [],
  "workingDirectory": "/absolute/server/path/to/meal-app",
  "sandboxMode": "danger-full-access",
  "networkAccess": true
}
```

`workingDirectory` 是服务所在电脑的绝对路径，不是手机路径。服务不会接受手机上传一个完整项目，也不会把客户端传入的本地路径当作输入文件。

当 task 结果为 `needs_input` 时，把其 `result.taskId` 放进 URL：

```bash
curl -sS -X POST http://127.0.0.1:7777/v1/tasks/替换为taskId/resume -H "Authorization: Bearer $CODEX_TASK_TOKEN" -H 'Content-Type: application/json' -d '{"prompt":"按单人份展示热量"}'
```

## 生命周期与磁盘占用

- 上传图片写到 `os.tmpdir()/codex-task/server/<job-id>/inputs`，任务结束即删除整个 `<job-id>` 目录。
- 服务启动时还会删除超过 job TTL 的崩溃残留上传目录，默认阈值为 24 小时。
- 远程 image 强制使用 CodexTask 受管临时产物，避免默认写满服务进程的当前目录。
- 终态 job 和 artifact 下载入口默认保留 24 小时；服务重启后，内存 job 记录立即消失。
- `codex-task gc` 清理过期受管图片与任务状态；不会删除显式输出路径或普通项目文件。
- 官方 Codex SDK sessions 位于 `$CODEX_HOME`，不归远程 job GC 管理。

## 安全边界

服务没有 TLS、用户账号或审批 UI。它提供 `text`/`image` 级别的设备 Token，但这不能代替网络隔离。不要把端口直接映射到公网。优先顺序是：

1. Tailscale/WireGuard 等私有 VPN。
2. 可信局域网，并设置主机防火墙只允许需要的网段。
3. 有身份认证和 HTTPS 的反向代理。

主 Service Token 允许调用全部接口，并可通过 task 触发服务器用户权限范围内的文件修改和命令。默认 task 是 `danger-full-access`、联网开启、`approval: never`。只需要文本或图片的客户端应使用受限设备 Token；仍建议在网络层限制调用方，或使用独立低权限系统用户。
